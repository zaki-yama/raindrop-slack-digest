## 1. [Intent to prototype and ship: Declarative Web Push](<https://groups.google.com/a/mozilla.org/g/dev-platform/c/dYIXpuf3I_s/m/RuDCIfB5AAAJ>)

groups.google.com

MozillaのDOM Core担当エンジニアが、Firefox 162でDeclarative Web Pushを全プラットフォームで既定有効にする意向を表明した。通知内容とクリック時のURLを含む特定のJSON形式でプッシュを送ることで、service workerをインストールせずに通知を表示できる。Push APIが使いやすくなり、service worker起動のコストも避けられる。

- Declarative Web Pushは、通知情報と遷移先URLを含む特定のJSON形式のプッシュメッセージで通知を表示する仕組み。
- service workerのインストールが不要になり、Push APIを使いやすくなる。
- service workerの起動コストを避けられるため、通知受信の効率が向上する。
- mutableプロパティは利用実績も開発者の関心もないため未実装(bug 2071418)。
- 制御用のPreferenceはdom.push.declarative.enabledとdom.push.window_pushmanager.enabled。
- 他ブラウザはWebKitがSafari 18.5で提供済み、Blinkは未実装。WPTでは現状テストできず、Mozilla独自テストを用意している。

## 2. [Reducing the Opportunity for Exploitation with Edge Lockdown Mode](<https://microsoftedge.github.io/edgevr/posts/Lockdown-Mode/>)

microsoftedge.github.io

Microsoft Edge が、標的型攻撃を受けやすいユーザー向けに攻撃面を減らす Lockdown Mode を Canary で提供開始した。JIT を無効化する Enhanced Security Mode を土台に、特権の高い GPU プロセスへ到達する WebGL や WebGPU を遮断する。互換性の低下と引き換えに保護を強める設計で、テスターからのフィードバックも募集している。

- Edge は更新の高速化、Rust による書き換え、攻撃面の削減という3方向で防御を進めている。
- Enhanced Security Mode は JIT を無効化し、2022年2月以降の悪用済み Chromium 脆弱性の55%から保護できたと分析している。
- Lockdown Mode の初期版は GPU プロセスを狙い、WebGL、WebGL2、WebGPU を遮断する。
- 現行の Canary 版で、観測された特権昇格エクスプロイトの約60%を軽減できたと分析している。
- ゲームや地図などのグラフィック重視サイトは動かない場合があり、サイト単位の例外設定を整備中。一般ユーザー向けの既定にはしない。
