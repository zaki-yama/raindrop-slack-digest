## 1. [テスト要求仕様（TRS）を書いてみたら、テスト設計が楽になった話](<https://zenn.dev/edash_tech_blog/articles/0d49bd338b64f0>)

zenn.dev

e-dashのQAチームが、テスト設計書の前にテスト要求仕様（TRS）を挟む運用を紹介する記事。仕様レイヤーでUS/UC/振る舞い/ACを確定し、テスト設計レイヤーで因子と水準を整理する。画面をまたぐ規模の機能で、切り分けの迷い、網羅確認、未決事項の管理が楽になったと報告している。

- 従来のテンプレートでは「確認項目 n」の切り方が書き手任せで、対象が大きいと全体を把握しにくかった。
- TRSは仕様レイヤー（基本情報・対象範囲・US・Gherkin形式のAC）とテスト設計レイヤー（因子一覧・制約・関連・組み合わせ・Open Issues）の2層構造。
- ACは可変部のみを<...>で書き、具体的な値は因子一覧が単一の情報源として持つ。
- 振る舞いを正常・準正常・例外に分け、該当なしは「なし」と明記するため、抜けが目に見える。
- Open Issuesは今回6件で、うち3件は仕様書の修正につながった。解決後も履歴として残す。
- TRSをエージェントに渡し、AC81本からテストケース360件を生成。人の作業は「書く」から「レビューする」に移る。
- AI支援時は実装を期待値の根拠にせず、仕様書とデザインに無ければ「未定義」として扱う。

## 2. [Mods の概要 - Claude Code Docs](<https://code.claude.com/docs/ja/plugins/mods/overview>)

code.claude.com

mod は Claude Code 内で実行されるプラグインで、JavaScript/TypeScript のフックでイベントを処理し、ペインの描画、ツール呼び出しの制御、独自コマンドの追加などを行える。この記事では、できること、インストール方法、セキュリティ上の注意、オン/オフの切り替え、動作する環境、他の拡張手段との比較、組み込み mod を説明している。

- mod は plugin.json、hooks.json、register.js の3ファイルで構成でき、tool.call や ui.render などのフックを登録する。
- settings hooks、skills、MCP サーバーと違い、Claude Code 内で動作し、インターフェイスの描画や再スタイル化ができる。
- mod はユーザー権限で動き、サンドボックス化されず、シークレットの読み取りやツール呼び出しの承認もできる。ただし権限プロンプトは変更できない。
- インストール前に claude plugin validate で、処理するイベントと要求する呼び出し(hooks: と calls: の行)を確認できる。
- フックは CLI と Desktop アプリで動くが、描画が表示されるのはターミナルと Desktop アプリのみ。無効化は /plugin、--safe-mode、disableAllHooks などで行う。

## 3. [Intent to Ship: CORS enforcement for Background Fetch](<https://groups.google.com/a/chromium.org/g/blink-dev/c/c-3hZsLwp3w/m/BJp0B4C2AAAJ>)

groups.google.com

Chrome 157 から、Background Fetch API が通常の fetch() と同様に CORS を強制する。これまで Background Fetch ではCORS などのセキュリティポリシーを意図せず回避できたため、仕様の意図に合わせて修正する。利用は極めて少なく、全ユーザーに有効な状態で出荷する計画。

- Chrome 157 から Background Fetch API が CORS を強制する。デスクトップと Android の両方で出荷する。
- Local Network Access チェックなど、通常の Fetch と同じセキュリティポリシーが適用される。
- Background Fetch を使えば CORS や CORP/COEP/DIP を回避できてしまう問題の修正である。
- Background Fetch の完全な廃止・削除も検討したが、より影響が大きいため見送った。
- サーバー側の設定(Access-Control-Allow-Origin など)が不足していると、一時的に動かなくなる可能性がある。
- Finch feature 名は BackgroundFetchCorsEnforcement。他ブラウザ(Gecko、WebKit)の意見は現時点でなく、仕様変更の予定もない。
