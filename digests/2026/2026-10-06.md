## 1. [TanStack Charts 1.0 | TanStack Blog](<https://tanstack.com/blog/tanstack-charts-1-0?via=dailydev>)

tanstack.com

TanStack Charts 1.0 の公開に合わせ、作者の Tanner Linsley が開発動機と設計思想を語る記事。D3、Chart.js 2.0、react-charts、Observable Plot の経験を踏まえ、mark を組み合わせて作る API を、AI に実装を任せつつ設計したという。1.0 は、この API を使う人を支える約束だと位置づけている。

- チャートは mark(線・点・棒)を scale、axes、interactions と合成して作り、新しいチャート種別を探す必要がない。
- カスタム mark、scale、renderer、interaction を作れ、scene contracts まで下りて細かく制御できる。
- データから scale、mark、interaction まで型情報が途切れないよう設計され、人にも AI にも扱いやすい。
- SVG が既定で、Canvas は別 import の別 renderer。アニメーションも必要なときに追加でき、D3 scale や compact scales も使える。
- bundle budget、テスト、ブラウザテストでサイズと品質を管理。1.0 は API 変更時も移行手段を用意するという約束を意味する。

## 2. [Intent to Prototype: CSS Linked Parameters for External SVGs](<https://groups.google.com/a/chromium.org/g/blink-dev/c/8FpImg92-4s/m/EMAJBJjUAAAJ>)

groups.google.com

Microsoftが提案するCSS Linked Parametersについて、Chromiumのblink-devに出されたIntent to Prototypeです。外部SVGに、参照元ページから名前付きCSS値を渡せるようにし、1つのキャッシュ済みファイルを異なるテーマで再利用できるようにします。値の渡し方や、SVG側での受け取り方、動機が説明されています。

- 外部SVGは、要素やCSSの画像プロパティから参照されると、参照元ページからスタイルを変更できない。
- パラメータは param(<dashed-ident>, <declaration-value>?) で宣言する。
- 値は link-parameters プロパティ、URL内のlink parameterディレクティブ、url()内のparam()修飾子のいずれかで渡せる。
- SVG側は env() でカスタム環境変数として値を読み、未指定時のフォールバックも指定できる。
- 従来の回避策には、インライン化による肥大化、テーマ別コピーによる重複、JSでの書き換えによる複雑化とCSPでの遮断があった。
