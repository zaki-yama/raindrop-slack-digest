## 1. [How and when to use subagents in Claude Code](<https://claude.com/ja/resources/articles/subagents-in-claude-code>)

claude.com

Claude Code の長いセッションではコンテキストが肥大化し、応答速度やトークンコストに影響する。この記事は、独立したコンテキストを持つサブエージェントの概要、使うべき場面、会話・カスタム定義・CLAUDE.md・skills・hooks といった呼び出し方、使わない方がよい場面を解説する。

- サブエージェントは独立したコンテキストウィンドウを持ち、作業後に関連する結果だけをメインの会話へ返す。
- 10ファイル以上の探索や、3つ以上の独立した作業がある場合は、サブエージェントに任せる目安になる。
- カスタムサブエージェントは .claude/agents/ に markdown で定義でき、description に具体的なトリガー条件を書くと委譲されやすい。
- CLAUDE.md は委譲のルール、skills はオンデマンドのワークフロー、hooks はイベント起点の自動化に向く。
- 順次依存する作業、同一ファイルの編集、小さなタスクでは不向き。サブエージェント同士の連携が必要なら agent teams を使う。

## 2. [eMudhraの中間CA証明書の秘密鍵を求めてみる](<https://zenn.dev/herumi/articles/search_bad_emudhra_key>)

zenn.dev

2026年10月に報告された認証局eMudhraの中間CA証明書の秘密鍵の脆弱性について、証明書の公開鍵から実際に秘密鍵を求める手順を紹介する記事。秘密鍵が8ビット以下だったため、洗練されたライブラリを使わずナイーブなPythonコードで総当たりして解いている。

- openssl s_client で dv-g3b-emudhra.we-have-a-problem.com の証明書を取得し、2番目の CN=EM DV TLS CA - G3B の証明書を使う。
- openssl x509 と openssl ec -pubin -text で公開鍵を読み出し、04に続くx座標・y座標を取り出して Ec クラスの点 Q にする。
- 曲線は secp384r1(NIST P-384)で、規格のベースポイント P に対して Q = xP となる x を求める離散対数問題になる。
- 通常 x は384ビット近く総当たりは不可能だが、今回は P を足し続けるだけで x = 156 が約0.4秒で求まった。
- 楕円曲線の演算コードは『Software Design 2022年3月号』の記事で使ったPython実装(src/ecc)を流用している。

## 3. [How the Claude Code team does code review / claude.dev Blog](<https://claude.dev/blog/solving-code-review-at-anthropic/>)

claude.dev

Claude Code のコードの約9割をClaudeが書く中で、チームは人の時間と注意を最も貴重な資源と捉え、レビューの大半を機械に移した。PRごとのAIレビュー、セキュリティレビュー、CI、リスクに応じた人の承認、マージキューやフラグ、迅速なロールバックを重ねる構成で、6〜9月にマージPRは2倍超、リバート率は40%超低下したという。

- レビューの目的を「人が読んだか」ではなく「何が壊れうるか、どのチェックが適切か」に置き換え、レビューを書きながら継続的に走らせる形にした。
- PR前にClaudeがテストやスクリーンショットで自己検証し、CLAUDE.md や REVIEW.md で繰り返し出る指摘をソース側で直す。
- 全PRにAIレビューが付き、複数エージェントが検出して投票で絞り込む。未解決の指摘やセキュリティ指摘が残るとマージできない。
- 人の承認はリスクを分類器で判定して低・中・高に応じて0〜2人とし、エージェントの承認は人の承認として数えない。
- インシデントをevalにして毎日採点し、50ラウンド超の事例を受けて3ラウンド上限や差分のみの再レビューを導入した。
