## 1. [This Month in Ladybird - October 2026 - Ladybird](<https://ladybird.org/newsletter/2026-10-31/?via=dailydev>)

ladybird.org

Ladybird の2026年10月の月次報告。スタイルとレイアウトを JavaScript と並行して別スレッドで動かす対応、LibJS の JIT、新しい WebAssembly エンジン、ブラウザ UI の刷新が主な内容。WPT での進捗、対応サイトの改善、セキュリティ強化、Rust 移行、アルファ版に向けた準備も紹介している。

- スタイル、レイアウト、ペイント記録を別スレッドに移し、JS 実行中でも CSS アニメーションや :hover が動作する。
- LibJS が Linux と macOS の x86-64 と AArch64 で、型プロファイルに基づく投機的最適化の JIT を使う。
- 新 Wasm エンジンは独自のインタプリタと JIT を持ち、例外処理や GC に対応し、JetStream 3 の Wasm で約7倍のスコアになった。
- WPT は AI コーディングエージェントによる修正も寄与して 75,650 subtests 増え、Safari Technology Preview を上回った。
- レンダラーのサンドボックス強化やプロセス分離の拡大、C++ から Rust への移行、alpha 向けのリリースビルドやクラッシュレポートの追加も進んだ。

## 2. [Intent to Prototype: Permissions Policy Header support in Firefox](<https://groups.google.com/a/mozilla.org/g/dev-platform/c/xkdfDI6qM3k/m/odLpx2JMCAAJ>)

groups.google.com

Mozilla の dev-platform に投稿された Intent to Prototype で、Firefox に Permissions-Policy HTTPレスポンスヘッダのサポートを実装する提案。サイトが自身のドキュメントや埋め込みドキュメントで、geolocation、camera、microphone などのブラウザ機能を使えるかを制御できるようになる。仕様は W3C のもので、対象は全プラットフォームである。

- Permissions-Policy ヘッダにより、サイトは自身と埋め込みドキュメントでの geolocation、camera、microphone などの利用を制御できる。
- 仕様は W3C の webappsec-permissions-policy で、追跡用バグは Bugzilla の 1694922 である。
- プラットフォームは全対象で、プリファレンスは dom.security.permissionsPolicy.header.enabled と dom.security.permissionsPolicy.experimental.enabled。
- 他ブラウザでは Blink が出荷済みで、WebKit は未出荷だが bug 253126 で作業中である。
- Standards-Positions の議論は mozilla/standards-positions の issue 24 にあり、web-platform-tests は permissions-policy で確認できる。
