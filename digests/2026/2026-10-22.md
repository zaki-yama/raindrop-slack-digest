## 2. [内製 Background Coding Agent “haro” で拓く未来の開発体験 - LayerX エンジニアブログ](<https://tech.layerx.co.jp/entry/why-we-built-our-background-agent>)

tech.layerx.co.jp

LayerX バクラク事業部が内製したクラウド型 Coding Agent「haro」を紹介する記事。大規模 monorepo でローカル開発が限界に達したことと、既製品では自社コードベースに合わないことが内製の動機とのこと。構成、社内での利用状況、コーディング以外への活用、今後の展望が書かれている。

- Agent 制御は TypeScript の Temporal Workflow で行い、AI SDK の HarnessAgent 経由でクラウド環境内の Claude Code 等を操作する。
- 環境は EKS 上で動き、CRD と Custom Controller(Go)でライフサイクルを管理する。
- Slack、Notion、Linear、Datadog、Snowflake や社内サービスの MCP が接続され、利用者は鍵管理なしに自分のアカウントで使える。
- 10月時点で PR の55〜60%(約200件)が haro 経由で、利用者は58名。モバイルチームでは Android エミュレーターが動くため PR の約75%が haro 経由。
- カスタム Agent、Scheduler、API 起動により、バグスキャン、指標集計、flaky test 修正などの自動化にも使われ、デザイナや QA にも利用が広がっている。
- セッションは原則公開で、ログを prompt や skill の改善に生かし、ループが自動で閉じる基盤を目指している。

## 3. [Your Browser Can Do WHAT?! 5 AI Features That Actually Work](<https://dev.to/sylwia-lask/your-browser-can-do-what-5-ai-features-that-actually-work-1blb?via=dailydev>)

dev.to

Transformers.js 4.3.1を使い、WebGPUとWebAssemblyでブラウザ内完結のAI機能を5つ試した記事。バックエンド不要でプライバシー面にも利点がある一方、WebGPU対応やモデルのダウンロードサイズ、精度に限界がある。著者は本番では任意の補助機能として使うべきだと結論づけている。

- React+TypeScriptで、Web Workerによる推論とオンデマンドのモデル読み込みを使い、AIバックエンドなしで動かしている。
- 背景除去はRMBG-1.4(約44Mパラメータ、約170MB)で、ECでの活用が考えられるが商用利用前にライセンス確認が必要。
- alt生成はFlorence-2-base-ft、チケット作成はQwen2.5-0.5B-Instructで、後者はプロンプト、パース、Zod検証でJSON出力を安定させた。
- 意味検索はall-MiniLM-L6-v2(約22Mパラメータ、23〜90MB)で、埋め込みとコサイン類似度により小さな特化モデルの有効性を示した。
- 制約として、WebGPUの対応差、モバイルでの遅さ、モデルのダウンロードサイズ、OCRや文脈付きalt生成が不十分だった点が挙がっている。

## 4. [Announcing TypeScript 7.1 Beta - TypeScript](<https://devblogs.microsoft.com/typescript/announcing-typescript-7-1-beta/?via=dailydev>)

devblogs.microsoft.com

TypeScript 7.1 Beta の新機能を紹介する記事。ambient module 宣言での import attributes 対応、source phase imports、es2026 ターゲット、複数のエントリポイントに分かれた新 API、Vue などの単一ファイルコンポーネント向けの content mappers が挙げられている。性能・メモリの最適化結果と、分配的な条件型に対するチェック厳格化も説明される。

- declare module "*" with { type: "css" } のように import attributes 付きで ambient module を宣言でき、属性の付け忘れをエラーにできる。
- import source 構文と import.source() に対応し、WebAssembly.instantiate へモジュールソースを渡せる。利用には --module と --lib/--target の設定が必要。
- --target/--lib es2026 が安定版となり、Math.sumPrecise()、Iterator.concat()、Error.isError() などが含まれる。
- 新 API は typescript/sync、async、fs、ast などに分割され、スナップショットと仮想ファイルシステムで差分更新ができる。
- tsconfig の contentMappers で .vue などの埋め込みコードを扱える。実行には --runExternalCode が必要。
- 7.0 比の --noEmit ビルドは mui-docs で 22.2s→11.9s、メモリは 8,093→4,079 MiB に減った。
- 分配的な条件型の型パラメータの制約チェックが厳しくなり、既存コードで新たなエラーが出る場合がある。

## 6. [SleeperWidget: How Ad-Driven Installs Activate Hidden Browser Extension Behavior](<https://microsoftedge.github.io/edgevr/posts/SleeperWidget-How-Ad-Driven-Installs-Activate-Hidden-Browser-Extension-Behavior/>)

microsoftedge.github.io

Microsoft Edge Extension Securityが、インストール経路によって挙動が変わるストア掲載拡張群「SleeperWidget」を分析した記事。View Point 3D Earth を例に、広告から有効化データの受け渡し、C2通信、検知回避の手口までを追っている。あわせてストア各社との連携対応と推奨事項も述べている。

- Edge、Chrome Web Store、Mozilla Add-ons にまたがる少なくとも250件の関連掲載を、メタデータやインフラ、挙動の組み合わせで特定した。
- 広告ランディングページが有効化チケットと識別子をlocalStorageに保存し、インストール後に拡張のcontent scriptが拡張ストレージへ写す。直接インストールにはチケットがなく休眠したままになる。
- 有効化後は全HTTP/HTTPSページのタイトルとURLをC2(/blase)へ送り、サーバーが返すURLで広告ページやアフィリエイトリンクを開く。拡張側は遷移先を検証しない。
- Sponsored content をオフにしても閲覧データの送信は止まらなかった。共有UIDにより、別の拡張同士も同一ユーザーとして紐づけられる。
- Shadow DOMでの広告表示、難読化手法の変更、サーバー側フラグによる休眠など、審査や検知を避ける工夫がある。
- Microsoftは2026年4月から該当拡張を削除し、100万超のクライアント識別子をマルウェアブロック状態にした。ChromeとMozillaにも指標を共有した。
