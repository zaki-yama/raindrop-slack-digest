## 1. [GitHub Actionsにロックファイルが来るぞ - Qiita](<https://qiita.com/access3151fq/items/70a93f08bffd9c5f09a5>)

qiita.com

GitHub Actionsの依存をコミットSHAでピン留めする公式gh拡張「gh actions-lock」(Technical Preview)の紹介記事。従来のSHA指定の問題点(推移的依存、Dependabotアラート対象外、手間)を整理し、導入手順、CIでの検証方法、周辺ツールの対応状況を2026年9月時点で解説している。

- SHA指定には、推移的依存が固定されない、Dependabotアラートの対象外、調べる手間という3つの問題があった。
- gh extension install github/gh-actions-lockで導入し、gh actions-lockでactions.lockを自動生成する。
- workflowには管理コメントが付き、3rd party actionはパッチバージョン指定に、Composite Actionは$/経由の参照に書き換わる。
- gh actions-lock --no-fixでピン留め漏れを検出でき、CIのLint stepに入れるとよい。
- GitHub Actionsはactions.lockに対応済み。Dependabotは更新PRでactions.lockを更新せず未対応で、Alertsの対応は未検証。

## 2. [Intent to Prototype: Prompt API Thinking Mode](<https://groups.google.com/a/chromium.org/g/blink-dev/c/QgKAo0a_bHs/m/ToSzsFsrCgAJ>)

groups.google.com

ChromeのBlink-devに投稿された、Prompt API(window.LanguageModel)へThinking Modeを追加するPrototype意図表明です。推論の努力量を段階指定でき、思考内容も必要に応じて取得できるようにします。Gemma 4などオンデバイスモデルの推論能力を、Web開発者が使えるようにする狙いです。

- セッション作成時やモデルへのprompt時に、effortとincludeThoughtsのオプションを渡して使う。
- effortは"none"、"low"、"medium"、"high"の意味的な4段階で、トークン予算などの内部設定に対応づけられる。
- 推論用の一時的なトークンはセッションの永続コンテキストから自動で除かれ、includeThoughts: true のときだけクライアントに返る。
- 推論により生成トークンが可視の回答の5〜20倍になり得るため、遅延と電池消費の観点でオプトイン方式にしている。
- Gemini、OpenAI、Anthropicなど主要なLLM APIも推論制御を公開しており、それに沿う形の提案である。マイルストーンは未定。

**🏷️ タグ:** `#Platform Updates`

## 4. [目を醒ませ 僕らの信頼が生成AIに侵略されてるぞ](<https://zenn.dev/spookies/articles/e70b80a510f5e2>)

zenn.dev

AI生成物を読まずに受け渡す「Meat Proxy」が連鎖した創作事例を通じ、出戻りの原因をAIのせいにせず、自分の責任として引き受けるべきだと論じるエッセイ。AIは責任主体になれずコパイロットにとどまるため、人間の価値は意思と責任にあると主張する。

- 事例ではクライアント、PL、エンジニアA、リードエンジニアの全員がAI生成物を理解せず次工程へ渡し、Meat Proxy化していた。
- 要件ずれによる出戻りはAI登場前からあり、AIにより損失が数人月から数人日に圧縮された点は評価すべきとする。
- 問題は「AIが暴走した」と自分に言い訳し、責任の自覚を失うことだと指摘する。
- 部下への委任なら監督責任だが、AIは責任主体になれないため、AIの暴走は使った本人の暴走になる。
- AIは自分が把握・理解できる範囲でコパイロットとして使い、意思と責任を持つため専門性の学習も怠らないよう説く。
