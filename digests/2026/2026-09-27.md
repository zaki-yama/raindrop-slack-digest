## 1. [Using Claude Code: Spending your effort / claude.dev Blog](<https://claude.dev/blog/spending-your-effort/>)

claude.dev

Claude Code の effort(モデルに使わせる計算量の目安)とは何か、どのレベルをいつ使うべきかを、玩具的なタスクと Terminal-Bench 3.0 の分析で検証した記事。effort は検証やエッジケースのテスト量、モデル自身の判断の度合いを調整するものだと結論づけている。

- effort を上げると、Claude が独自判断で行う検証やエッジケースのテストが増える。アプローチ自体が誤っている場合は改善しにくい。
- 曖昧な指示のアプリ開発では effort で作り込みが大きく変わる。詳細な仕様(インタビュー形式で作成)を与えると、effort が違っても成果物は近くなる。
- 著者の開発ループは、インタビューで仕様化、low で実装、レビュー、high で検証という流れ。
- Terminal-Bench 3.0 では html-js-filter が Fable 5.1 で low 1/5 から xhigh 5/5 になった。分野別ではセキュリティ 64%→87%、ハードウェア 34%→75%。
- 目安は、low がブレスト・簡単な変更、medium が通常の実装、high が既存コードのバグ修正など検証重視の作業、max が完全自律で難題を解くとき。

## 2. [What a task costs on Opus 5.5 / claude.dev Blog](<https://claude.dev/blog/what-a-task-costs-on-opus-5-5/>)

claude.dev

Claude Code でタスク1件あたりのコストが何で決まるかを、Opus 5.5 の API 定価(入力$4/出力$20/キャッシュ読み$0.20 per 1M)を使った例で解説する記事。Opus 5 からの価格変更、effort・モデル選択・キャッシュ・compaction の運用、/usage での実測方法を扱う。

- タスクのコストはターン数、キャッシュ読み、出力(thinking含む)トークン、モデルで決まる。各ターンが会話全体を再送するため、ターン数が増えると高くなる。
- Opus 5.5 は Opus 5 より入出力が20%安く、キャッシュ読みは60%安い。同一トークン数の例示セッションでは約31%安く、「40%安い」は少ないトークン使用を仮定した推定値と説明している。
- effort は medium を基本とし、詰まったら high に上げる。テストなど自己検証手段を与えることが先決で、それでも駄目なら大きいモデル(Fable 5.1)へ移る。
- キャッシュはモデル切替、MCP接続変更、待機超過、compactなどで書き直しが発生する。5分キャッシュの書き込みは読みの約25倍なので、セッション設定は最初に済ませる。
- 検索・ログ読みのサブエージェントは Sonnet/Haiku に振り、コード編集は Opus 5.5 に残す。/usage で同じタスクを2モデルで実測して比較することを勧めている。
